# 2. Functional requirements audit and traceability matrix

Date: 2026-11-12. Source baseline: `a4aac3a`. Documentation-only assessment.

## Scope and interpretation

This matrix audits the available user requests, supplied trade messages, [current runbook](./startTradeRunbook.md), [running guide](./RUNNING.md), [handoff](./HANDOFF.md), implementation and existing tests. It supplements the [architecture/reliability audit](./ARCHITECTURE_RELIABILITY_AUDIT.md). No complete signed-off functional specification or complete historical conversation transcript is available. The 33 rows below cover identifiable functional obligations and explicitly identified policy gaps; they are not an invented exhaustive business specification.

Provenance: **U** = explicit user request in available conversation; **D** = documented behavior, not necessarily owner-approved; **G** = audit-derived gap needing an owner decision. When U and D conflict, the contradiction is recorded rather than resolved by assuming implementation is authoritative.

Classification meanings:

- **Correctly implemented:** the narrowly stated behavior is supported by source and existing test evidence, not a guarantee of end-to-end reliability.
- **Partially implemented:** a meaningful subset exists but important conditions are uncovered or unsupported.
- **Incorrectly implemented:** actual behavior contradicts the stated obligation or a reproducible functional expectation.
- **Missing:** no implementation of an explicit requested capability was found.
- **Ambiguous:** a unique expected behavior cannot be established without a business decision.
- **Not verifiable:** evidence is insufficient to determine whether the claimed outcome holds.

Each ID appears in both matrices: A supplies intent, clarity, implementation and classification; B supplies exception/edge-case analysis and measurable acceptance criteria. **ACs are proposed verification criteria, not claims of passing tests or newly approved business rules.** Conditional criteria remain blocked on the named open question. No arbitrary timing, risk or profitability threshold is silently introduced.
